Un seul contrat d'envoi.

Service, canal, pays : trois champs, un seul appel. Vos développeurs intègrent une fois, vous changez de canal sans changer de code.

Le contrat, en bref

service

Ce que vous envoyez : sms, whatsapp, otp. Un seul crédit, facturation par canal utilisé.

canal

Comment ça part : sms ou whatsapp. Même campagne, chaque canal avec sa validation.

pays

Où ça part : CI et Afrique de l'Ouest et du Centre. Une grille, un crédit.

Exemples d'appel

Envoi via API REST. Clé via en-tête X-Api-Key (clé test disponible dans le bac à sable). Webhooks d'accusés : livré, lu, impossible.

curl -X POST https://api.izi-sendz.cloud/api/v1/tenant/messages/send \
  -H "X-Api-Key: VOTRE_CLE" \
  -H "Content-Type: application/json" \
  -d '{"service":"sms","channel":"sms","country":"CI","address":"tel:+2250700000001","content":"Rappel : RDV demain à 10h. Répondez OUI pour confirmer.","senderName":"MABOUTIQUE"}'
const res = await fetch("https://api.izi-sendz.cloud/api/v1/tenant/messages/send", {
  method: "POST",
  headers: { "X-Api-Key": "VOTRE_CLE", "Content-Type": "application/json" },
  body: JSON.stringify({ service: "sms", channel: "sms", country: "CI", address: "tel:+2250700000001", content: "Rappel : RDV demain à 10h. Répondez OUI pour confirmer.", senderName: "MABOUTIQUE" })
});
const data = await res.json();
console.log(data.resourceId);

OTP via API : WhatsApp puis repli SMS

Votre application appelle l'API avec le numéro de votre cible : l'OTP part par WhatsApp, avec repli SMS si WhatsApp n'est pas reçu. Facturation : unités SMS et WhatsApp selon les canaux intervenus ; le message WhatsApp est servi si vous disposez d'unités WhatsApp.

{
  "service": "otp",
  "channel": "whatsapp",
  "fallbackChannel": "sms",
  "country": "CI",
  "address": "tel:+2250700000001",
  "content": "Votre code : 4821. Il expire dans 5 min."
}
